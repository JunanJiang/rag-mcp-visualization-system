## 2. 接入场景与选择

SimuReport 开放了四种接入形态，按"改造成本从低到高"排列：

| 场景 | 说明 | 谁适合 | 改造成本 |
|------|------|--------|:----:|
| **A. 独立使用** | 用户直接访问 SimuReport Web，与你的产品完全解耦 | MVP 阶段、联合部署试点 | ⭐ |
| **B. REST API 调用** | 你的后端通过 HTTP 调用 SimuReport 接口，UI 仍是你自己的 | 有成熟前端、仅需 SimuReport 的"生成能力" | ⭐⭐ |
| **C. MCP 协议调用** | 你的 AI 助手 / 脚本通过 MCP 协议调用 SimuReport 工具 | 有 AI 对话模块、想动态发现能力 | ⭐⭐ |
| **D. 嵌入式 UI** | 在你的产品里通过 iframe / 弹窗打开 SimuReport 页面，复用全部 UI | 想快速拥有完整报告体验 | ⭐⭐⭐ |

**四种方式可以组合**。比如最常见的是 **B + D**：后端用 REST 调用 + 前端嵌入报告预览窗口。

### 2.1 决策树

```
你需要的是……
│
├─ 只是偶尔跑一次报告？→ A. 独立使用（把 URL 发给用户就行）
│
├─ 你已经有自己的报告 UI，只想借用生成能力？
│  └─ B. REST API 调用
│
├─ 你有 AI 对话助手，想让它调 SimuReport 能力？
│  └─ C. MCP 协议调用
│
├─ 想让用户在你软件里直接看到完整报告界面？
│  └─ D. 嵌入式 UI（可以和 B/C 组合）
│
└─ 都不确定？→ 先读本指南第 9 节的 integration_demo 参考实现
```

## 3. 部署架构

### 3.1 服务拓扑

SimuReport 完整部署由四个服务组成，你可以按需启动其中任意子集：

```
┌─────────────────────────────────────────────────────────────────┐
│                         第三方宿主软件                           │
│  （你的仿真 / 可视化产品，任意前端技术栈：Qt / Electron / Web）  │
└────────────────┬──────────────────────────┬─────────────────────┘
                 │ REST / MCP               │ iframe
                 │ (场景 B / C)             │ (场景 D)
                 ▼                          ▼
       ┌──────────────────┐       ┌──────────────────────┐
       │  主后端 5000      │◄──────┤   主前端 3001        │
       │  (SimuReport)    │       │   (Vue)              │
       │  /api/*  /mcp/*  │       └──────────────────────┘
       └────┬─────────────┘
            │
            │  可选：你可以完全跳过下面两个 demo 服务
            │  只用主后端 + （可选）主前端即可完成接入
            ▼
       ┌──────────────────┐       ┌──────────────────────┐
       │  集成演示后端 5100 │◄──────┤  集成演示前端 3002   │
       │  (参考实现)       │       │  (参考实现)          │
       └──────────────────┘       └──────────────────────┘
```

### 3.2 端口与职责

| 端口 | 服务 | 职责 | 是否必须 |
|:----:|------|------|:----:|
| 5000 | 主后端 | 所有 `/api/*` 与 `/mcp/*` 接口；数据包解析；RAG；报告生成 | ✅ 必须 |
| 3001 | 主前端 | 完整 SimuReport UI；管理员后台；嵌入式页面目标 | 只要用场景 D 就需要 |
| 5100 | 集成演示后端 | 模拟"接入方后端"的**参考实现**；代理层；可供你复制改造 | 仅供参考 |
| 3002 | 集成演示前端 | 模拟"接入方前端"的**参考实现**；演示工具栏按钮、插件面板 | 仅供参考 |

### 3.3 最小部署（场景 B / C 专用）

如果你只需要 REST / MCP 调用、完全不需要 SimuReport 的前端 UI：

```bash
# 你只需要起主后端
pip install -r requirements.txt
python server/app_v2.py
```

然后你的后端通过 HTTP 调 `http://<server>:5000/api/*` 即可。

### 3.4 完整部署（场景 D 需要）

```bash
# 项目根目录双击运行（Windows）
启动项目.bat

# 或手动启动
python server/app_v2.py               # 主后端 5000
python integration_demo/backend/app.py  # 集成演示后端 5100
cd frontend && npm run dev            # 主前端 3001
cd integration_demo/frontend && npm run dev  # 集成演示前端 3002
```

批处理内置**就绪探测**：先等主后端 `/api/health` 返回 200，再拉其他服务，避免启动竞争。

## 4. 身份与会话

### 4.1 两套凭证（务必分清）

- **接入 Api Key（你要关心的）**：由 SimuReport 管理员为你签发；你的后端调 SimuReport 时携带
- **LLM 密钥池（你不用管）**：SimuReport 内部调大模型时用；管理员在后台配置，对集成方完全不暴露

### 4.2 获取接入 Api Key

**让 SimuReport 管理员执行**：

```bash
# 1) 管理员登录
curl -X POST http://<simureport>:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<admin_password>"}'
# → { "token": "<jwt>" }

# 2) 签发一条专属你的 Api Key（raw_key 只展示一次）
curl -X POST http://<simureport>:5000/api/admin/api-keys \
  -H "Authorization: Bearer <jwt>" \
  -H "Content-Type: application/json" \
  -d '{"name":"<你的产品名 - 生产环境>"}'
# → { "id": 3, "raw_key": "sr_7f8a9b..." }
```

管理员把 `raw_key` 通过安全渠道发给你。**之后所有的后端-后端调用都通过这个 key 鉴权**。

### 4.3 Api Key 的使用

```bash
curl -X POST http://<simureport>:5000/api/<endpoint> \
  -H "Authorization: ApiKey sr_xxx..." \
  -H "Content-Type: application/json" \
  -d '<payload>'
```

**安全建议**：
- ❌ **不要**把 Api Key 硬编码在前端代码或移动 App 里（会被逆向）
- ✅ 放在你自己的后端配置（环境变量 / 密钥管理服务）
- ✅ 请求统一由你的后端代理，前端只和你的后端通信
- ✅ 如果 Key 泄漏，立即让 SimuReport 管理员调用 `DELETE /api/admin/api-keys/<id>` 停用

### 4.4 用户身份的传递（场景 D 专用）

如果你要把 SimuReport 页面嵌入你的产品（场景 D），还需要解决"用户免登"问题——不能让用户在你的软件里登录一次、进入 SimuReport 页面后再登一次。

**SimuReport 提供的桥接方案**：一个特殊的登录透传页 `/integration-entry`，接收 URL 参数后写入 localStorage 跳转：

```
http://<simureport-frontend>:3001/integration-entry?
  token=<simureport_jwt>&
  user=<base64(JSON(userObject))>&
  context=<base64(JSON(contextObject))>&
  redirect=/v2
```

**参数说明**：

| 参数 | 是否必须 | 内容 |
|------|:----:|------|
| `token` | ✅ | 对应用户在 SimuReport 的 JWT（你的后端先调 `/api/auth/login` 拿到） |
| `user` | 推荐 | Base64 编码的用户对象 JSON，如 `{"id":7,"username":"alice","display_name":"Alice","role":"user"}` |
| `context` | 可选 | Base64 编码的上下文对象，如当前数据包信息；会写入 `localStorage.integration_context` |
| `redirect` | 可选 | 登录成功后要跳的主前端路径，默认 `/v2` |

页面加载后会：
1. `token` 写入 `localStorage.token`
2. `user` 解码后写入 `localStorage.user`
3. `context` 解码后写入 `localStorage.integration_context`
4. 跳转到 `redirect?resume=1&source=integration-demo`

### 4.5 典型会话流

**你的后端流程**（场景 B + D）：

```python
import base64, json, requests

SIMUREPORT_API = "http://simureport-backend:5000"
SIMUREPORT_WEB = "http://simureport-frontend:3001"
MY_API_KEY = "sr_7f8a9b..."  # 从环境变量读

def bridge_user_to_simureport(my_user):
    """在你的软件里点击"打开报告页"时调用"""
    # 1) 用 API Key 以你的身份登录 / 或创建 SimuReport 对应账号
    #    （简化：这里假设你的后端已经在 SimuReport 里给每个用户映射了账号）
    resp = requests.post(
        f"{SIMUREPORT_API}/api/auth/login",
        headers={"Authorization": f"ApiKey {MY_API_KEY}"},
        json={"username": my_user.simureport_username,
              "password": my_user.simureport_password}
    )
    token = resp.json()["token"]
    user_obj = resp.json()["user"]

    # 2) 构造桥接 URL
    user_encoded = base64.b64encode(json.dumps(user_obj).encode()).decode()
    ctx = {"source": "my_simulation_tool", "case_id": "case_001"}
    ctx_encoded = base64.b64encode(json.dumps(ctx).encode()).decode()

    return (f"{SIMUREPORT_WEB}/integration-entry?"
            f"token={token}&user={user_encoded}"
            f"&context={ctx_encoded}&redirect=/v2")
```

前端拿到这个 URL 直接 `window.open()` 或放进 iframe 的 `src`。

## 5. 数据包推送的三种方式

不论你的仿真数据从哪来，接入 SimuReport 前需要把它变成 **DataPackage**（参见《数据包规范文档》）。推送有三种方式：

### 5.1 方式 A：本地路径

你的产品和 SimuReport 部署在同一台机器（或有共享文件系统）时用这个最省事。

```bash
curl -X POST http://<simureport>:5000/api/upload-folder \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -d '{"path":"E:/my_tool_export/case_001"}'
```

**返回**：

```json
{
  "success": true,
  "path": "E:/my_tool_export/case_001",
  "info": {"format": "Plot3DMultiBlock", "blocks": 11, "variables": [...]}
}
```

### 5.2 方式 B：ZIP 上传

部署分离时用这个。你把 DataPackage 打包成 ZIP 后 multipart 上传：

```bash
curl -X POST http://<simureport>:5000/api/upload \
  -H "Authorization: ApiKey sr_xxx" \
  -F "file=@my_datapackage.zip"
```

### 5.3 方式 C：标准 Schema JSON

完全脱离文件系统、纯接口驱动：

```bash
curl -X POST http://<simureport>:5000/api/ingest \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "manifest": {"spec_version":"1.0","dataset":{"datasetType":"Custom","blockCount":1}},
    "variables": [{"name":"P","rangeGlobal":{"min":101325,"max":103500}}]
  }'
```

适合你的产品无本地文件、数据存在内存或数据库里的情况。

## 6. 一键生成工作流

这是**最常见的集成路径**：你的后端调一个接口，SimuReport 返回生成好的 Markdown / Word 文件 URL。

### 6.1 同步调用

```bash
curl -X POST http://<simureport>:5000/api/v1/report/generate \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "data": { "path": "E:/my_export/case_001" },
    "config": {
      "domain": "external_aero",
      "purpose": "design_validation",
      "phenomena": ["shock_wave","flow_separation"],
      "enable_org_kb": false
    }
  }'
```

**返回**：

```json
{
  "success": true,
  "mode": "sync",
  "report_id": 128,
  "files": {
    "markdown": "/api/download/md",
    "word": "/api/download/docx"
  },
  "quality": { "total_score": 84 }
}
```

下载：

```bash
curl -O -J -H "Authorization: ApiKey sr_xxx" \
  http://<simureport>:5000/api/download/docx
```

### 6.2 异步调用（长任务推荐）

如果数据量大、希望不阻塞：

```bash
curl -X POST http://<simureport>:5000/api/v1/report/generate \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "async": true,
    "data": {"path": "E:/large_case"},
    "config": {"domain":"external_aero"}
  }'
# → { "task_id": "task_abc123", "mode": "async" }

# 轮询
curl http://<simureport>:5000/api/tasks/task_abc123 \
  -H "Authorization: ApiKey sr_xxx"
# → { "task": { "status": "running", "progress": 0.45 } }
# → { "task": { "status": "success", "result": {...} } }
```

### 6.3 SSE 流式（实时进度）

想在自己软件里显示"生成中……正在处理第 3 章"之类的实时进度：

```bash
curl -N -X POST http://<simureport>:5000/api/workflow/auto-generate-stream \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "config": {"domain":"external_aero","phenomena":["shock_wave"]}
  }'
```

SSE 会推送 `stage` / `progress` / `done` / `error` 事件。集成前端可以直接解析事件流驱动进度条。

## 7. MCP 接入最小示例

如果你的产品里有 AI 对话助手或脚本化能力调用，建议走 MCP。

### 7.1 发现工具

```bash
curl -X POST http://<simureport>:5000/mcp/tools/list \
  -H "Authorization: ApiKey sr_xxx"
```

返回 **OpenAI function calling 格式**的工具清单（共 12 个工具，详见《MCP 工具文档》）。

### 7.2 调用工具

```bash
curl -X POST http://<simureport>:5000/mcp/tools/call \
  -H "Authorization: ApiKey sr_xxx" \
  -H "Content-Type: application/json" \
  -d '{"name":"rag_query","arguments":{"query":"Plot3D 多块结构网格","top_k":3}}'
```

### 7.3 在你的 AI 助手里挂接工具（Python）

```python
import json, requests
from openai import OpenAI  # 你自己的 LLM 客户端

def fetch_simureport_tools():
    r = requests.post(f"{SIMUREPORT}/mcp/tools/list",
                      headers={"Authorization": f"ApiKey {MY_KEY}"})
    return r.json()["tools"]

def call_simureport_tool(name, args):
    r = requests.post(f"{SIMUREPORT}/mcp/tools/call",
                      headers={"Authorization": f"ApiKey {MY_KEY}"},
                      json={"name": name, "arguments": args})
    return json.loads(r.json()["result"])

# 把 SimuReport 工具注册进你自己的 LLM 对话
client = OpenAI()
tools = fetch_simureport_tools()
messages = [{"role": "user", "content": "帮我分析当前数据包的激波区域"}]

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=messages,
    tools=tools
)

# 根据 tool_calls 调用 SimuReport
for call in resp.choices[0].message.tool_calls or []:
    name = call.function.name
    args = json.loads(call.function.arguments)
    result = call_simureport_tool(name, args)
    # 回传给 LLM 继续 ...
```

这样你就把 SimuReport 的 12 个工具**无缝挂进了你自己的 AI 对话**。

## 8. 嵌入式 UI 接入

### 8.1 iframe 嵌入

最简方案：

```html
<iframe
  id="simureport-frame"
  src="http://<simureport>:3001/integration-entry?token=<jwt>&user=<b64>&context=<b64>"
  style="width: 100%; height: 100%; border: none;"
></iframe>
```

**注意事项**：
- 主前端默认允许被嵌入（已配置 `X-Frame-Options` 与 CSP）
- 如果跨域，需要浏览器允许第三方 cookie 或者使用相同域部署
- iframe 内的路由跳转不会影响外层宿主

### 8.2 消息通信（可选）

如果你想在 iframe 外部知道内部状态（比如用户什么时候导出了报告），可以监听 `postMessage`：

```javascript
// 宿主软件的前端
window.addEventListener('message', (event) => {
  if (event.origin !== 'http://<simureport>:3001') return;
  const msg = event.data;
  if (msg.type === 'report_exported') {
    console.log('用户导出了报告:', msg.report_id);
    // 触发你自己产品里的通知、关闭弹窗等
  }
});
```

> 注：目前 SimuReport 主前端尚未全面铺开 `postMessage` 事件，这是**规划中的扩展点**。短期内建议通过后端的 `/api/auth/reports` 轮询获取状态。

### 8.3 会话恢复

用户点进 SimuReport 页面后，系统会自动调 `GET /api/session/context` 恢复：

```json
{
  "user": {"id": 7, "username": "alice", "role": "user"},
  "hasDataPackage": true,
  "dataPackage": {
    "path": "E:/my_export/case_001",
    "name": "case_001",
    "info": {"datasetType": "Plot3DMultiBlock", "blockCount": 11, ...}
  },
  "hasDraft": false,
  "progress": null,
  "recommendedStep": "clarification"
}
```

`recommendedStep` 告诉前端应该停在哪一步：`upload` / `clarification` / `generate`。

**你的典型用例**：在桥接前先调 `/api/upload-folder` 把数据包装载好，然后打开 iframe，用户进来看到的就是"跳过了上传步骤"的状态。

## 9. 参考实现：integration_demo

项目自带一份完整的参考实现，在 `integration_demo/` 目录下，**强烈建议你先跑起来看一遍**。

### 9.1 目录速览

```
integration_demo/
├── backend/
│   ├── app.py              ← 集成端后端（Flask，监听 5100）
│   └── requirements.txt
└── frontend/
    ├── package.json
    ├── vite.config.js
    └── src/
        ├── App.vue         ← 模拟"第三方仿真软件"的主界面
        ├── api.js          ← 封装对集成端后端的调用
        └── main.js
```

### 9.2 集成端后端做了什么

`integration_demo/backend/app.py` 的职责 = "**你在自己产品里需要写的后端代码**"：

| 职责 | 对应端点 / 方法 |
|------|----------------|
| 调 SimuReport 登录、包装成自己的登录 | `POST /api/login` |
| 上传数据包并持久化 session token | `POST /api/upload` |
| 代理 `auto-generate-stream` SSE | `POST /api/workflow/stream` |
| 代理 `mcp-chat-stream` SSE | `POST /api/mcp-chat-stream` |
| 生成跳转 URL 给前端打开主系统网页 | 返回 `/integration-entry?...` 格式的 URL |
| 代理报告下载 | `GET /api/download/<type>` |

**你可以把 `app.py` 的逻辑原样移植到你自己的后端技术栈**（Express / Spring / Go / .NET 均可）。

### 9.3 集成端前端做了什么

`integration_demo/frontend/src/App.vue` 模拟的是"你自己仿真软件的 UI 壳子"：

- 顶部工具栏：**"智能可视化"按钮**（模拟你产品里要加的入口）
- 右侧插件面板（点按钮后弹出）：
  - **MCP 工具清单展开器**（体现"工具发现"能力）
  - **AI 控制台**：支持自然语言驱动（"帮我生成报告"→ 自动调工具链）
  - **一键生成按钮**：绑定到 `/api/workflow/auto-generate-stream`
  - **打开网页端按钮**：触发生成桥接 URL 并 `window.open`
  - **报告回传区**：展示生成进度、下载链接

### 9.4 怎么把参考实现改成你自己的

```
参考实现                            →    你的实现
-----------                              -----------
integration_demo/frontend/              你已有的仿真软件 UI
  src/App.vue 的"智能可视化按钮"    →    你软件工具栏的新按钮
  右侧插件面板                       →    你软件的侧栏 / 弹窗 / 扩展页

integration_demo/backend/               你已有的后端
  app.py 的路由和代理逻辑             →    移植到你的后端技术栈
  （保持 API 契约一致即可）
```

最快的改造路径：**先原样跑通 integration_demo，再一步步替换**。

## 10. 常见问题与故障排查

### 10.1 启动类

| 问题 | 排查 |
|------|------|
| 端口 5000 已被占用 | `netstat -ano \| findstr 5000`（Windows）/ `lsof -i :5000`（Mac/Linux），杀掉占用进程或改端口 |
| 主后端启动后 `/api/health` 没响应 | 检查控制台是否有异常栈；检查 ChromaDB 初始化是否报错 |
| `启动项目.bat` 卡住 | 批处理内部会等主后端 ready；如果主后端启动失败会一直等。先单独跑 `python server/app_v2.py` 看错误 |
| 前端 3001 白屏 | 浏览器控制台看网络请求；确认 `vite.config.js` 里的 proxy 指向 5000 |

### 10.2 鉴权类

| 问题 | 排查 |
|------|------|
| 所有接口都返回 401 | 检查 `Authorization` Header 格式。`Bearer <jwt>` 和 `ApiKey sr_xxx` 是两种**不同格式**，别混写 |
| `/api/admin/*` 返回 403 | 你用的账号不是管理员。让管理员调用 `PUT /api/admin/users/<uid>/role` 给你升权 |
| API Key 之前能用，突然 401 | 可能被停用。让管理员调 `GET /api/admin/api-keys` 看状态，必要时重新签发 |
| `/api/user/ai-config` PUT 返回 403 | 这是故意的。LLM 密钥由管理员统一管理，普通用户无法修改 |

### 10.3 数据包类

| 问题 | 排查 |
|------|------|
| 上传后说"未识别的数据包格式" | 检查 `manifest.json` 是否存在且 `dataset.datasetType` 字段非空 |
| 验证返回 `errors` | 按错误信息逐条修复，或临时用 `skip_validation=true`（不推荐） |
| 报告生成时变量描述为空 | 变量缺 `rangeGlobal`。补齐 `min/max` 后重新上传 |
| Chinese / 中文文件名导致解析失败 | 图片和操作目录**尽量用 ASCII 命名**，manifest 内容可以用中文 |

### 10.4 生成类

| 问题 | 排查 |
|------|------|
| `generate_next_slot` 返回"未创建 Draft" | 调用顺序错了，得先 `auto_configure` 或 `/api/clarification/submit` |
| 生成卡很久不返回 | 检查 LLM 密钥池是否有启用配置、网络能否访问大模型服务 |
| 生成内容明显偏题 | 检查 `phenomena` 配置是否准确；检查是否关闭了有用的 KB 层 |
| SSE 连接很快断开 | 检查反向代理是否开启了缓冲（nginx 需要 `proxy_buffering off`） |

### 10.5 iframe 嵌入类

| 问题 | 排查 |
|------|------|
| iframe 显示"refused to connect" | X-Frame-Options 或 CSP 冲突。确认部署时没有覆盖默认配置 |
| `/integration-entry` 跳转后仍然在登录页 | token 无效。确认 token 是从 `/api/auth/login` 拿的、没过期 |
| 用户在 iframe 里登录后外层宿主不知道 | 当前没有 `postMessage` 事件。短期用后端轮询；长期考虑 SimuReport 新增事件通道 |

## 11. 附录

### 11.1 环境变量速查

| 变量 | 作用 | 必须 |
|------|------|:----:|
| `TAVILY_API_KEY` | 联网搜索 | 否 |
| `DEBUG_MODE` | 详细错误栈 | 否（开发时 = 1） |
| `SIMUREPORT_DATA_DIR` | 数据包默认目录 | 否（有默认值） |
| `SIMUREPORT_KB_DIR` | 知识库文档目录 | 否 |

> **LLM 密钥不从环境变量读**。初始部署时，让管理员登录后调用 `POST /api/admin/ai-keys` 添加第一条 LLM 配置。

### 11.2 端口占用表

| 端口 | 服务 | 可改 |
|:----:|------|:----:|
| 5000 | 主后端 | ✅（改 `server/app_v2.py` 里的 `app.run(port=...)`） |
| 3001 | 主前端 | ✅（改 `frontend/vite.config.js` 里的 `server.port`） |
| 5100 | 集成演示后端 | ✅ |
| 3002 | 集成演示前端 | ✅ |

### 11.3 日志位置

| 日志 | 位置 |
|------|------|
| 主后端运行日志 | 控制台（默认）或 `server/logs/app.log`（若开启） |
| MCP 工具调用日志 | 通过 `GET /api/mcp/logs` 查询 |
| 审计日志 | 通过 `GET /api/admin/audit-logs` 查询（管理员） |
| 数据包验证结果 | 通过 `POST /api/data-package/validate` 取回 |

### 11.4 最小依赖

- **网络**：可访问 SimuReport 主后端 5000 端口

- **HTTP 客户端**：任意语言的 `requests` / `fetch` / `httpx` 等
- **可选**：SSE 解析能力（如果用流式接口）
