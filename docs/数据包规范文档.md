## 1. 概述

**DataPackage** 是一个**文件夹**（或等效 ZIP 压缩包），里面放仿真数据的 **JSON 元信息** 和 **可视化截图**。报告生成引擎通过统一的适配层解析该文件夹，抽取出"事实（facts）"，再驱动 RAG 检索与大模型生成。

一句话：**DataPackage 是仿真平台与 SimuReport 之间的"契约格式"**。仿真平台只要产出合规的 DataPackage，就能接入 SimuReport；SimuReport 也只认 DataPackage，不关心上游是 Fluent、CFX、OpenFOAM 还是自研工具。

## 2. 设计理念

### 2.1 清单驱动（Manifest-Driven）

所有数据包以 `manifest.json` 为入口。清单声明"本包含有哪些内容、各在什么位置"，其他文件是对清单的展开。这带来三个好处：

- **自描述**：读取 `manifest.json` 就知道整包概况；
- **增量扩展**：新增字段不影响旧解析器；
- **引用解耦**：子文件的命名可以不固定，通过 `manifest.exports` 指向即可。

### 2.2 分层解耦

```
层级       关注点
-----      -------------------
顶层       这是什么样的数据？     → manifest.json
变量层     变量怎么命名、范围？    → variables.json
网格层     网格怎么分块、尺寸？    → datasets.json
语义层     数据之间的组织关系？    → hierarchy.json
视图层     默认怎么看？          → views/view_presets.json
过程层     工程师看了什么？       → automation/ops/*
视觉层     截图证据链            → images/
```

每一层相互独立：变量变了不用改层级，视图变了不用改数据结构。

### 2.3 向前兼容

- 未知字段被忽略，不报错
- 缺少 `spec_version` 视为 `0.9-legacy`，会尝试兼容解析并给出 warning
- `REQUIRED_FILES`（`manifest.json` / `variables.json`）之外的一切都是可选的

│   ├── geometry/

## 4. 必需文件

### 4.1 `manifest.json`

数据包的入口，声明规范版本、数据集元信息与文件引用。

**完整示例**：

```json
{
  "spec_version": "1.0",
  "app": {
    "name": "SimuVision-Desktop",
    "version": "1.0.0"
  },
  "createdAt": "2026-04-19T11:22:14",
  "sessionId": "session_20260419_112214_plot3d",
  "dataset": {
    "datasetName": "wing_case_01",
    "datasetType": "Plot3DMultiBlock",
    "blockCount": 11,
    "totalPoints": 1002672,
    "totalCells": 922816
  },
  "exports": {
    "datasets": "datasets.json",
    "variables": "variables.json",
    "hierarchy": "hierarchy.json",
    "images": ["images/geometry/overview.png", "images/mesh/overview.png"],
    "viewPresets": "views/view_presets.json"
  },
  "sourceFiles": {
    "gridFile": "path/to/plot3d.g",
    "solutionFile": "path/to/plot3d.q"
  }
}
```

**字段说明**：

| 字段 | 类型 | 必须 | 说明 |
|------|------|:----:|------|
| `spec_version` | string | 推荐 | 规范版本号，当前为 `"1.0"` |
| `app.name` | string | 否 | 导出应用名称 |
| `app.version` | string | 否 | 导出应用版本 |
| `createdAt` | string | 否 | ISO 8601 时间戳 |
| `sessionId` | string | 否 | 会话标识（调试追踪用） |
| `dataset.datasetType` | string | **是** | 数据集类型枚举（见下） |
| `dataset.datasetName` | string | 否 | 数据集名称 |
| `dataset.blockCount` | int ｜ string | 否 | 网格块数量（字符串会被转 int） |
| `dataset.totalPoints` | int | 否 | 总网格点数 |
| `dataset.totalCells` | int | 否 | 总网格单元数 |
| `exports` | object | 否 | 引用其他 JSON 文件的相对路径 |
| `sourceFiles` | object | 否 | 上游原始文件路径（记录用） |

**`datasetType` 枚举**：

| 值 | 说明 |
|----|------|
| `Plot3DMultiBlock` | Plot3D 多块结构网格 |
| `Plot3DSingleBlock` | Plot3D 单块结构网格 |
| `VTKUnstructured` | VTK 非结构网格 |
| `OpenFOAM` | OpenFOAM 格式 |
| `FluentCase` | ANSYS Fluent 格式 |
| `Custom` | 自定义格式（需要注册适配器） |

### 4.2 `variables.json`

流场变量清单，至少包含一个变量。

**完整示例**：

```json
{
  "variables": [
    {
      "name": "F1V1",
      "guess_variableName": "density",
      "components": 1,
      "location": "PointData",
      "rangeGlobal": { "min": 0.128, "max": 3.007 }
    },
    {
      "name": "F1V2",
      "guess_variableName": "MomentumX",
      "components": 1,
      "location": "PointData",
      "rangeGlobal": { "min": -314.46, "max": 869.04 }
    },
    {
      "name": "Velocity",
      "guess_variableName": "velocity",
      "components": 3,
      "location": "PointData",
      "rangeGlobal": { "min": 0.0, "max": 523.8 }
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必须 | 说明 |
|------|------|:----:|------|
| `name` | string | **是** | 变量原始名称（如 `F1V1`、`Pressure`） |
| `guess_variableName` | string | 推荐 | 语义推测名称（如 `density`、`MomentumX`、`Pressure`）；便于大模型理解 |
| `components` | int | 否 | 分量数（标量=1，矢量=3，张量=6/9），默认 1 |
| `location` | string | 否 | 数据位置：`PointData` 或 `CellData` |
| `rangeGlobal.min` | number | 推荐 | 全局最小值 |
| `rangeGlobal.max` | number | 推荐 | 全局最大值 |

> `rangeGlobal` 是 **SimuReport 的关键输入**——它驱动 `compute_metrics` 等工具和报告里"密度跨度"、"速度峰值"这些事实性陈述。缺失时会降级为"无范围数据"。

## 5. 推荐文件

### 5.1 `datasets.json`

网格块详情，包含每个块的空间范围、维度和拓扑信息。

**完整示例**：

```json
{
  "datasets": [
    {
      "blockIndex": 0,
      "name": "Block_1",
      "datasetId": "block_0000",
      "type": "vtkStructuredGrid",
      "topology": {
        "dims": { "values": [216, 24, 72] },
        "points": 373248,
        "cells": 351095
      },
      "bounds": {
        "values": [-0.5, 1.5, -0.2, 0.2, -0.3, 0.3]
      },
      "metadata": {
        "region": "main_flow",
        "comment": "主流核心区"
      }
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `blockIndex` | int | 块序号（从 0 起） |
| `name` | string | 块名称（人类可读） |
| `datasetId` | string | 块唯一 ID |
| `type` | string | 块类型：`vtkStructuredGrid` / `vtkUnstructuredGrid` / `vtkPolyData` |
| `topology.dims.values` | array\<int\>（长度 3） | i/j/k 维度 |
| `topology.points` | int | 该块网格点数 |
| `topology.cells` | int | 该块单元数 |
| `bounds.values` | array\<number\>（长度 6） | `[xmin, xmax, ymin, ymax, zmin, zmax]` |
| `metadata` | object | 自定义元数据（系统会 as-is 保留） |

## 6. 可选文件

### 6.1 `hierarchy.json`

声明数据之间的**语义层级关系**——哪些块属于哪个逻辑组件、哪些变量属于哪个物理类别等。系统**以 as-is 方式保留**到 facts 里，供大模型生成时做结构化引用。

**建议结构**：

```json
{
  "hierarchy_type": "component_based",
  "components": [
    {
      "name": "wing_surface",
      "display_name": "机翼表面",
      "block_ids": ["block_0000", "block_0001"],
      "role": "boundary",
      "importance": "high"
    },
    {
      "name": "wake_region",
      "display_name": "尾迹区",
      "block_ids": ["block_0007", "block_0008"],
      "role": "analysis_focus",
      "importance": "high"
    }
  ],
  "variable_groups": [
    {
      "name": "conservative_quantities",
      "display_name": "守恒量",
      "variables": ["F1V1", "F1V2", "F1V3", "F1V4", "F1V5"]
    },
    {
      "name": "derived_quantities",
      "display_name": "派生量",
      "variables": ["Velocity", "Pressure", "Mach"]
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `hierarchy_type` | string | 层级类型标识（如 `component_based` / `region_based`） |
| `components[]` | array | 组件列表（可选） |
| `components[].name` | string | 组件内部名 |
| `components[].display_name` | string | 展示名（报告中使用） |
| `components[].block_ids` | array\<string\> | 该组件关联的块 ID（对应 `datasets.json` 的 `datasetId`） |
| `components[].role` | string | 组件角色：`boundary` / `domain` / `analysis_focus` / `reference` |
| `components[].importance` | string | `high` / `medium` / `low`（用于 RAG 权重） |
| `variable_groups[]` | array | 变量分组（可选） |

> 本字段仅作为**建议结构**。系统不强制字段形式，任何满足 JSON 语法的对象都会被保留。建议至少遵循以上约定，以便报告生成时能给出结构化引用。

## 7. images 目录

存放可视化截图，按用途分三个子目录：

```
images/
├── geometry/
│   ├── overview.png              ★ 推荐 — 几何整体概览
│   ├── cross_section.png         ○ 可选
│   └── blocks/                   ○ 可选 — 分块几何
│       ├── block_0.png
│       ├── block_1.png
│       └── ...
├── mesh/
│   ├── overview.png              ★ 推荐 — 网格整体概览
│   ├── near_wall.png             ○ 可选
│   └── blocks/                   ○ 可选 — 分块网格
│       ├── block_0.png
│       └── ...
└── variables/
    ├── F1V1_slice.png            变量云图（命名自由，建议含变量名）
    ├── F1V2_contour.png
    └── Velocity_streamlines.png
```

### 7.1 命名约定

- **扩展名**：`.png`（推荐）或 `.jpg`
- **编码**：文件名用 ASCII 字符（中文会导致某些工具链报错）
- **分块图片**：建议命名为 `block_<index>.png`，与 `datasets[].blockIndex` 对齐
- **变量图片**：建议含变量名前缀（`F1V1_slice.png` 等），便于大模型关联

### 7.2 图片的引用约束

- 引擎在解析时会 **自动扫描** `images/geometry/` `images/mesh/` `images/variables/` 三个目录，**不需要**在 `manifest.exports.images` 显式列出
- `manifest.exports.images` 只是一个提示清单，用于集成方快速知道"有哪些关键图"，不做强约束

## 8. automation 目录

记录用户在仿真后处理过程中执行的**自动化操作**（如等值线提取、剖面抽取、矢量图生成等），以**一个操作一个子目录**的方式组织。

### 8.1 目录结构

```
automation/
└── ops/
    ├── contour_extract_001/      ← 操作 ID（建议 <operation>_<seq>）
    │   ├── context.json              ★ 操作上下文
    │   ├── result.json               ☆ 执行结果
    │   └── images/
    │       ├── screenshot_001.png
    │       └── screenshot_002.png
    ├── velocity_vectors_001/
    │   └── ...
    └── profile_sampling_001/
        └── ...
```

### 8.2 `context.json`（必须）

描述操作的类型和参数：

```json
{
  "operation_type": "contourLine",
  "timestamp": "2026-04-19T11:28:00",
  "parameters": {
    "variable_name": "F1V1",
    "num_contours": 20,
    "color_map": "jet",
    "value_range": [0.128, 3.007],
    "cutting_plane": {
      "origin": [0.0, 0.0, 0.0],
      "normal": [0.0, 1.0, 0.0]
    }
  },
  "user_comment": "在 y=0 平面提取密度等值线，聚焦激波区"
}
```

**字段说明**：

| 字段 | 类型 | 必须 | 说明 |
|------|------|:----:|------|
| `operation_type` | string | **是** | 操作类型标识：`contourLine` / `streamLine` / `vectorField` / `profileSampling` / `sliceExtract` 等 |
| `timestamp` | string | 否 | 操作时间 |
| `parameters` | object | **是** | 操作参数，至少含 `variable_name` |
| `parameters.variable_name` | string | **是** | 关联变量名（引擎按此做关联） |
| `user_comment` | string | 否 | 用户备注（写入报告时可作为"工程师意图"的佐证） |

### 8.3 `result.json`（推荐）

描述操作的执行结果：

```json
{
  "success": true,
  "timestamp": "2026-04-19T11:28:05",
  "image_files": ["screenshot_001.png", "screenshot_002.png"],
  "statistics": {
    "points_sampled": 12430,
    "range_observed": [0.131, 2.895]
  },
  "note": "生成 20 条等值线，已导出 2 张截图"
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 是否成功 |
| `image_files` | array\<string\> | 本次操作产生的图片**文件名**（相对于 `images/` 子目录） |
| `statistics` | object | 统计数据（可选，引擎会保留） |
| `note` | string | 简短说明 |

### 8.4 验证规则

- `automation/ops/<op>/context.json` **必须存在**（否则触发 warning）
- `result.json` 可缺失
- `images/` 目录可缺失（操作可以无截图）

## 9. views 目录

### 9.1 `view_presets.json`

保存视角预设（相机位置、朝向等），用于前端复现关键视图。

**完整示例**：

```json
{
  "presets": [
    {
      "id": "iso_default",
      "name": "等轴测默认视图",
      "camera": {
        "position": [2.5, 2.5, 2.5],
        "focalPoint": [0.5, 0.0, 0.0],
        "viewUp": [0.0, 0.0, 1.0]
      },
      "clipping_range": [0.1, 100.0],
      "parallel_projection": false,
      "background_color": [0.1, 0.1, 0.1]
    },
    {
      "id": "top_view",
      "name": "俯视图",
      "camera": {
        "position": [0.5, 0.0, 5.0],
        "focalPoint": [0.5, 0.0, 0.0],
        "viewUp": [0.0, 1.0, 0.0]
      },
      "parallel_projection": true
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必须 | 说明 |
|------|------|:----:|------|
| `presets[].id` | string | **是** | 预设 ID（唯一） |
| `presets[].name` | string | 推荐 | 展示名 |
| `presets[].camera.position` | array\<number\>（3） | **是** | 相机位置 |
| `presets[].camera.focalPoint` | array\<number\>（3） | **是** | 相机朝向点 |
| `presets[].camera.viewUp` | array\<number\>（3） | **是** | 视图上方向 |
| `presets[].clipping_range` | array\<number\>（2） | 否 | 近远裁剪面 |
| `presets[].parallel_projection` | boolean | 否 | 是否正交投影，默认 false |
| `presets[].background_color` | array\<number\>（3，0-1） | 否 | 背景色 RGB |

> 视角预设仅作为**元数据**保留。SimuReport 当前不会主动渲染视角（渲染仍由上游工具完成），但会把预设信息写入报告附录，供回放使用。

## 10. 最小合规示例

**最精简的数据包**只需要两个文件：

```
mini_package/
├── manifest.json
└── variables.json
```

**`manifest.json`**：

```json
{
  "spec_version": "1.0",
  "dataset": {
    "datasetName": "hello_world",
    "datasetType": "Custom",
    "blockCount": 1,
    "totalPoints": 1000,
    "totalCells": 900
  }
}
```

**`variables.json`**：

```json
{
  "variables": [
    {
      "name": "P",
      "guess_variableName": "Pressure",
      "rangeGlobal": {"min": 101325, "max": 103500}
    }
  ]
}
```

这个 2 文件、0 图片的"打招呼"数据包就可以被系统接受并跑通整个报告流程。当然，报告的生成质量会因图片缺失而大打折扣——**建议至少补一张 `images/geometry/overview.png` + 一张 `images/mesh/overview.png`**。

## 11. 验证

### 11.1 通过 HTTP API 验证

```
POST /api/data-package/validate
```

**请求**：

```bash
# 前置：通过 /api/upload-folder 或 /api/ingest 先装载数据包
curl -X POST http://localhost:5000/api/data-package/validate \
  -H "Authorization: ApiKey sr_xxx"
```

**返回**：

```json
{
  "is_valid": true,
  "spec_version": "1.0",
  "errors": [],
  "warnings": [
    "manifest.json 未声明 spec_version，建议添加 \"spec_version\":\"1.0\"",
    "automation/ops/op_abc/ 缺少 context.json"
  ]
}
```

### 11.2 通过 Python API 验证

```python
from reportgen.io.datapackage_spec import validate_data_package
from pathlib import Path

result = validate_data_package(Path("./my_package"))
is_valid = result["is_valid"]
for e in result["errors"]:
    print(f"  ❌ {e}")
for w in result["warnings"]:
    print(f"  ⚠️ {w}")
```

### 11.3 验证规则摘要

| 检查项 | 级别 | 说明 |
|--------|:----:|------|
| `manifest.json` 存在且可解析 | ❌ 错误 | 缺失 → 验证失败 |
| `variables.json` 存在且可解析 | ❌ 错误 | 缺失 → 验证失败 |
| `manifest.spec_version` 存在 | ⚠️ 警告 | 建议声明 |
| `manifest.dataset.datasetType` 非空 | ❌ 错误 | 缺失 → 无法选择适配器 |
| `variables[].name` 非空 | ❌ 错误 | — |
| `variables[].rangeGlobal` 存在 | ⚠️ 警告 | 建议补齐，否则 metrics 工具降级 |
| `images/` 存在但无图片 | ⚠️ 警告 | 空目录是异常信号 |
| `automation/ops/<op>/context.json` 存在 | ⚠️ 警告 | 缺失 → 该操作无法被解析 |

## 12. 从现有格式迁移

如果你的仿真平台已经有自己的输出格式（Plot3D、CGNS、OpenFOAM case 目录等），**无需改动原有格式**，只需额外输出一份 DataPackage 即可。以下是常见迁移路径。

### 12.1 从 Plot3D（`.g` + `.q`）迁移

```python
# 伪代码：在你的后处理脚本里调用
def export_to_simureport_datapackage(grid_file, solution_file, output_dir):
    # 1. 读取 Plot3D（用现有库，比如 vtk.vtkMultiBlockPLOT3DReader）
    blocks, variables = load_plot3d(grid_file, solution_file)

    # 2. 写 manifest.json
    write_json(f"{output_dir}/manifest.json", {
        "spec_version": "1.0",
        "app": {"name": "YourTool", "version": "1.0"},
        "dataset": {
            "datasetType": "Plot3DMultiBlock",
            "blockCount": len(blocks),
            "totalPoints": sum(b.points for b in blocks),
            "totalCells": sum(b.cells for b in blocks)
        },
        "sourceFiles": {"gridFile": grid_file, "solutionFile": solution_file}
    })

    # 3. 写 variables.json
    write_json(f"{output_dir}/variables.json", {
        "variables": [
            {"name": v.name, "components": v.ncomp,
             "rangeGlobal": {"min": v.vmin, "max": v.vmax}}
            for v in variables
        ]
    })

    # 4. 可选：写 datasets.json（含每块的维度、bounds）
    # 5. 可选：渲染几何/网格概览图 → images/geometry/overview.png 等
```

### 12.2 从 OpenFOAM case 目录迁移

```
OpenFOAM case/           →   DataPackage/
├── constant/                  ├── manifest.json
│   ├── polyMesh/              │   (dataset.datasetType = "OpenFOAM")
│   └── transportProperties    ├── variables.json
├── 0/                         │   (extracted from internalField)
│   ├── U                      ├── datasets.json
│   ├── p                      │   (mesh statistics)
│   └── T                      └── images/
└── system/                        (ParaView 批处理渲染)
```

建议用 ParaView 的 Python 脚本自动渲染几张标准视图。

### 12.3 从 Fluent / CFX 迁移

用各自的导出 CLI 先转成 CGNS 或 EnSight，再按上面 Plot3D 流程类推。

## 13. 扩展新格式

如果你的格式不在现有适配器支持列表里，可以**注册自定义适配器**。

### 13.1 实现适配器

在 `reportgen/io/adapters/` 下新建 `my_format.py`：

```python
from pathlib import Path
from typing import Dict, Any, List

from .base import DataPackageAdapter


class MyFormatAdapter(DataPackageAdapter):
    @property
    def format_name(self) -> str:
        return "MyFormat/v1"

    @property
    def format_description(self) -> str:
        return "我司自定义仿真数据包格式"

    def detect(self, data_dir: Path) -> bool:
        # 识别依据：目录下存在 my_signature.json
        return (data_dir / "my_signature.json").exists()

    def get_required_files(self) -> List[str]:
        return ["my_signature.json"]

    def parse(self, data_dir: Path) -> Dict[str, Any]:
        # 把自家格式解析为标准 facts 字典
        return {
            "data_dir": str(data_dir),
            "manifest": {"dataset_type": "MyFormat/v1", ...},
            "variables": [...],
            "datasets": {"blocks": [...], ...},
            "images": {"geometry": [], "mesh": [], "variables": []},
            "hierarchy": None,
            "automation_ops": [],
            "view_presets": []
        }
```

### 13.2 注册适配器

在 `reportgen/io/adapters/__init__.py` 的 `ADAPTER_REGISTRY` 中添加：

```python
from .my_format import MyFormatAdapter

ADAPTER_REGISTRY = [
    SimuVisionAdapter(),
    MyFormatAdapter(),     # ← 新增
    # ...
]
```

### 13.3 验证注册成功

```bash
curl http://localhost:5000/api/schema
# 返回体里应能看到 MyFormat/v1
```

## 附录 A：标准化 facts 字典结构

所有适配器都将原始格式解析为以下**统一结构**（供 SimuReport 内部使用）：

```python
{
    "data_dir": str,                # 数据包路径
    "manifest": {
        "app_name": str,
        "app_version": str,
        "dataset_type": str,        # Plot3DMultiBlock 等
        "dataset_name": str,
        "block_count": int,
        "total_points": int,
        "total_cells": int,
        "created_at": str,
        "session_id": str,
        "source_files": dict,
        "exports": dict,
    },
    "variables": [                  # 列表长度 >= 1
        {
            "name": str,
            "guess_variableName": str,
            "components": int,
            "location": str,
            "range_min": float | None,
            "range_max": float | None,
        },
    ],
    "datasets": {
        "block_count": int,
        "blocks": [...],
        "total_points": int,
        "total_cells": int,
    },
    "images": {                     # 键名固定
        "geometry": [str, ...],
        "mesh": [str, ...],
        "variables": [str, ...],
        "automation": [str, ...],
        "geometry_blocks": [str, ...],
        "mesh_blocks": [str, ...],
    },
    "hierarchy": dict | None,       # 原样保留
    "automation_ops": [             # 每个元素对应一个 op 目录
        {
            "folder": str,
            "operation_type": str,
            "variable_name": str,
            "parameters": dict,
            "success": bool,
            "images": [str, ...],
        },
    ],
    "view_presets": [...],          # 原样保留 presets 数组
    "_validation": dict,            # 验证结果（可选）
}
```

## 附录 B：字段速查表

| 文件 | 顶级字段 | 必须？ |
|------|---------|:----:|
| `manifest.json` | `spec_version` / `app` / `dataset` / `exports` / `sourceFiles` | `dataset.datasetType` 必须 |
| `variables.json` | `variables[]` | 至少 1 条 |
| `datasets.json` | `datasets[]` | 推荐 |
| `hierarchy.json` | 自由 | 否 |
| `views/view_presets.json` | `presets[]` | 否 |
| `automation/ops/<op>/context.json` | `operation_type` / `parameters` | 目录存在则必须 |
| `automation/ops/<op>/result.json` | `success` / `image_files` | 否 |
